# HaloAI 系统架构

## 为什么全栈使用 TypeScript

HaloAI 的主要复杂度来自实时交互、类型化事件、模型流式输出、权限判断和协作文档状态。这些层都可以使用 TypeScript 实现，无需引入第二种应用语言。特殊文档转换或受限计算将来仍可通过 HTTP/MCP 隔离，但不能侵入协作核心。

## 总体结构

```text
Web / PWA
  → 应用路由和流式响应
  → 协作服务
       → 授权策略
       → 房间和消息服务
       → 文档与版本服务
       → 审批与审计服务
       → Agent 协调器
            → 模型供应商适配器（由系统管理员配置，按租户分配后才可调用）
            → 工具策略网关
            → 隔离执行 / MCP 适配器
  → PostgreSQL / 对象存储 / 事件流
```

## 领域规则

### 主体、角色与成员关系

- `Actor` 是人员、AI 或内部系统身份。
- `Role` 是可以复用的权限集合。
- `Membership` 把某个 Actor 以某种角色加入工作空间或项目。
- `AgentProfile` 描述模型、指令、工具、记忆和预算，但本身不授予访问权限。

这种分离使同一人员或 AI 可以在不同项目承担不同职责，同时避免复制身份或把权限藏在提示词中。

### 协作模式

- `mention`：只有被明确提及的 AI 参与。
- `facilitated`：协调员选择最少的相关参与者。
- `workflow`：由耐久流程图控制顺序和人工审批点。
- `roundtable`：有固定轮次、参与人数和预算的讨论，由汇总者收束。

MVP 默认使用 `mention`，因为它可预测、成本低且容易审计。

### 记忆作用域

- 单次运行上下文：一次 Agent 运行结束后即可丢弃。
- 主体记忆：个人偏好，只能在策略允许的范围读取。
- 项目记忆：经过确认的事实、决定和产出物。
- 工作空间知识：经过治理、允许多个项目使用的资料。

原始聊天不能自动升级为长期记忆。

## 演进方式

### 基础阶段

Next.js 承载界面与当前阶段的 BFF 路由；浏览器认证和会话请求经 Web 同源转发到 API，避免跨端口 Cookie 被浏览器拒绝。客户端不必配置公开 API 地址。PostgreSQL 是登录会话、房间与消息的事实来源。本地启动需要数据库，并用 `DEMO_MODE` 控制是否写入虚拟数据，而不是跳过认证。协作路径只持久化人类消息，Agent 流式回复尚未接入。

模型由平台运营接入：系统管理员维护可用模型，再分配给租户。工作空间不能自己接供应商。

### 团队内测

增加独立 TypeScript 实时服务，处理 WebSocket presence、输入状态、消息分发和 Yjs 更新；Agent 任务进入耐久队列，Web 应用保持无状态。

### 企业阶段

增加隔离 Worker、网络出口策略、密钥代理、SSO/SCIM、不可篡改审计导出、数据保留以及区域化模型路由。
