# 认证、会话与工作空间初始化

## 1. 目标

本规格定义人员登录身份、可撤销浏览器会话、首次工作空间创建、成员邀请与角色变更。认证只证明“这个人是谁”；Membership 与 AccessRole 才决定其在具体工作空间中能做什么。

## 2. 认证边界

- 邮箱和密码由成熟认证组件处理，密码使用内存硬化哈希并仅保存在 credential Account 中。
- 浏览器只接收 `HttpOnly`、`SameSite=Lax` Cookie；会话令牌禁止进入 `localStorage`、URL、日志或错误响应。登录页经 Web 同源转发认证与会话请求，避免浏览器把 3000/3100 分端口或 `localhost` 与 `127.0.0.1` 混用当成第三方 Cookie 拒绝。
- 会话保存在 PostgreSQL，默认 7 天到期、每天滑动续期，退出和安全事件可以立即撤销。这里的“续期”是轮换可撤销的不透明会话 Cookie，不是把 access token 或 refresh token 暴露给浏览器脚本。
- 当前只有同源 Web/BFF 客户端，继续使用数据库会话 Cookie，不向浏览器脚本暴露 access token 或 refresh token，也不把令牌放入 `localStorage`。这样可以避免两套令牌、刷新竞态和 XSS 可读凭据；当原生客户端、第三方 API 或跨域资源服务器成为真实需求时，再在 AuthGateway 后引入 access/refresh 协议。
- 认证 Origin 与 CORS 使用显式白名单；禁止关闭 CSRF 或 Origin 检查。
- 认证数据库角色只访问 User、Account、Session 与 Verification 表，不能读取工作空间正文。
- 注册、登录和邀请接受返回稳定错误码，不泄露邮箱是否已存在或邀请属于哪个工作空间。

## 3. 首次初始化

已认证且没有工作空间的用户进入初始化向导：

1. 输入团队名称；
2. 生成规范 slug，冲突时要求显式调整；
3. 在单个事务中创建 Workspace、Human Actor、active Owner Membership 与内置角色；
4. 创建完成后返回工作空间摘要和当前 Actor，不自动安装工具或创建 AI。

创建事务必须先生成服务端 UUID，再以该 UUID 设置 PostgreSQL 工作空间上下文。客户端不能选择 `workspaceId`、`actorId` 或 Owner 身份。

## 4. 邀请与接受

- Owner 和 Admin 可以邀请；不能授予高于自身委托上限的角色。
- 邀请令牌至少 32 字节随机值，数据库只保存 SHA-256 摘要，默认 72 小时失效且只能消费一次。
- 邀请绑定规范化邮箱、目标工作空间和请求角色；登录邮箱不一致时拒绝。
- 接受邀请在同一事务中创建或恢复 Human Actor、Membership 与内置角色分配。
- 重复接受返回幂等结果；过期、撤销或邮箱不符使用不泄露工作空间信息的统一错误。
- 系统级租户管理员激活邀请与普通成员邀请分表保存，令牌同样只保存摘要、绑定邮箱、72 小时失效且只能消费一次。未注册邮箱不得获得系统生成的默认密码；受邀人必须通过认证组件自行设置密码。空间只在激活成功时创建，避免产生没有 active Owner 的半成品租户。

## 5. 角色与 Owner 保护

- 内置角色为 `owner`、`admin`、`member`、`guest`，协议值不本地化。
- 角色变更由服务端依据当前 Membership 决策，客户端传入角色只是请求值。
- 降级、暂停或移除 Owner 前锁定工作空间和成员记录。
- 数据库延迟约束保证工作空间始终存在至少一个 active Owner；应用层必须提前返回可理解的稳定错误。
- 撤权后新请求立即失败，进行中的 Agent 在下一个授权检查点停止。

## 6. 当前交付边界

Alpha 首先交付邮箱密码注册登录、会话查询与退出、工作空间创建和列表、邀请创建与接受、内置角色变更。本地 `DEMO_MODE=true` 会写入带 scrypt 哈希的演示账号，供前后端联调；该开关不能跳过 Cookie 会话或服务端授权。邮件投递尚未接入时，开发环境可以显示一次性邀请链接，但生产环境禁止在响应或日志中返回原始令牌。

登录页在协作成员和空间管理入口用下拉选择工作区，放在账号密码下方；系统管理不显示该项。打开登录页不复用已有 Cookie 去填充工作区，避免刷新后空凭证仍能进入。邮箱密码在本页提交成功后，再读取 `GET /v1/session` 填入下拉，并默认选中第一个（或上次记住的）工作区。系统管理入口必须再调用平台访问检查，只有 active `system_administrators` 记录才能进入。没有工作区时保持空态并导向初始化向导。客户端保存的 `workspaceId` 只是界面偏好，不能作为授权真相。账户菜单中的「切换工作区」仅在工作区数量大于 1 时出现。根路径 `/` 按上次选择的门户进入对应表面；账户菜单展示当前表面身份，进入某个表面时同步写入门户偏好，避免重启后停在协作前台却仍显示系统管理。

## 7. 验收

- 未登录请求不能创建、枚举或管理工作空间。
- 登录页仅在协作成员和空间管理显示工作区下拉，放在账号密码下方；选项只在本页登录成功后从会话读取，并默认选中第一项。刷新登录页不得靠已有 Cookie 跳过凭证。系统管理不显示该项。
- 空邮箱或空密码不得进入工作区；本地演示账号必须使用数据库中的哈希密码通过 `/api/auth/sign-in/email` 登录。
- Cookie 具备 HttpOnly、SameSite 和环境对应的 Secure 属性。
- 跨 Origin 状态变更被拒绝。
- 用户可创建首个工作空间并成为唯一 Owner。
- Owner 可邀请成员；错误邮箱、过期令牌和重复消费安全失败。
- 系统管理员用未注册邮箱创建租户时返回待激活状态；受邀人自行设置密码并激活后才创建空间和 Owner。生产响应与日志永远不含原始激活令牌。
- 最后一位 Owner 不能被降级、暂停或移除。
- 退出后原会话立即失效。
- 认证设置页面显示的有效期与续期间隔必须来自服务端实际配置，不能展示不生效的前端默认值；系统管理员授权不能由 Workspace 角色推导。
- 根路径 `/` 按上次门户进入对应表面；账户菜单展示当前表面身份，不得在协作前台残留「系统管理」。
