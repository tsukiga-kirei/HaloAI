# HaloAI 交付路线

> 当前进度：阶段 0 已形成可运行框架；阶段 1 已完成 PostgreSQL 基础、真实登录会话、工作区创建/切换、邀请接受、成员列表与内置角色保护。房间、消息与文档的耐久 HTTP 数据链路仍待接入。

## 阶段 0——规格与基础

- 完整的中英文产品、UX、领域、安全与架构规格。
- 产品级响应式导航和视觉系统。
- 类型化领域模型、权限策略和 Agent 契约。
- 中英文消息目录与主题 token。
- 演示对话与共享文档体验。
- 仓库级开发约束和质量门槛。

- PostgreSQL repository 与 migration（基础已完成，继续扩展身份、文档与运行 repository）。
- [x] 认证、工作空间创建/切换、邀请接受和内置角色保护。
- [x] 工作空间审计、已分配模型目录、只读安全快照、成员停用/恢复与账户显示名。

- 本地文档版本与人工审批流程。

### 当前非 AI 耐久数据切片

本切片先完成项目、项目成员、房间、房间成员和文档元数据的 REST 链路，不提前实现消息发送、模型调用或 Agent Run：

- 工作区 Owner/Admin 可以创建项目；项目创建者自动成为 `lead`。
- Owner/Admin 与项目 `lead` 可以把当前工作区的活跃人员加入项目；加入私有房间前必须先是项目成员。
- 项目成员只能列出自己有权访问的项目；私有房间仅显式房间成员可见，工作区可见房间仍要求项目成员身份。
- `lead` 和 `contributor` 可以创建房间与文档元数据；`reviewer` 和 `observer` 保持只读。
- 浏览器不得提交或覆盖可信的 `workspaceId`、`actorId`、成员角色或资源归属；API 从会话和服务端成员关系推导这些字段。
- 跨工作区 ID、缺失项目成员、已撤销房间成员和不允许的项目角色都必须失败关闭。
- 协作前台在真实认证模式下从 API 加载项目、房间和文档目录；本地 Demo 模式继续使用隔离的示例数据。

验收时，负责人能够创建项目、把成员加入项目、创建私有房间与文档元数据；刷新页面后数据仍存在，且整个路径不会调用 AI。

## 阶段 2——团队 Beta

- WebSocket presence 与可靠消息投递。
- 基于 Yjs 的协同编辑、评论和建议模式。
- 耐久任务队列、重试、取消和恢复。
- 受治理的知识来源和权限感知检索。
- 模型密钥库（系统侧）、按租户分配、成本面板和使用限额。
- PWA 安装、推送通知与离线草稿。

## 阶段 3——受控执行

- MCP 注册表和每个 Agent 独立工具白名单。
- 隔离的 TypeScript Worker 与受限网络出口。
- 外部和不可逆行为审批收件箱。
- 签名 Webhook、集成身份和不可篡改审计导出。
- SSO、SCIM、保留、法律冻结与企业部署配置。

## 成功指标

- 从创建房间到产生第一份被接受成果的时间。
- AI 建议被采纳或编辑进入最终文档的比例。
- 在纠错率不升高的前提下节省的人工审阅时间。
- 每条被接受贡献的成本与延迟。
- 被拒绝或升级审批的风险行为，以及策略误报率。
