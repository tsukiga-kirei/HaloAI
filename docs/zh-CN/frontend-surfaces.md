# 前台、工作空间后台与系统后台

## 1. 目的

HaloAI 将面向团队的协作体验、工作空间治理和平台运营明确拆成三个界面区域。拆分首先服务于心智模型和最小权限，而不是为了制造更多页面。

| 区域         | 稳定路由   | 使用者                                        | 核心职责                                                                       |
| ------------ | ---------- | --------------------------------------------- | ------------------------------------------------------------------------------ |
| 协作前台     | `/app`     | 团队成员与受邀访客                            | 房间、消息、文档、AI 协作、审批和成果交付                                      |
| 工作空间后台 | `/admin/*` | Workspace Owner、Workspace Admin 与专项管理员 | 成员、角色、AI（只用已分配模型）、集成、安全、用量与审计                       |
| 系统后台     | `/system`  | 平台运营与安全人员                            | 租户生命周期、整套模型目录与按租户分配、系统健康和全局策略；不默认读取租户内容 |

根路由 `/` 只负责进入协作前台，不承载第二份首页。

## 2. 导航与视觉边界

- 协作前台固定为左导航与右工作区：左侧白色菜单和个人设置，右侧灰色当前页面；禁止在主工作区重复左侧一级导航。
- 工作空间后台与系统后台共用协作前台同一套侧栏：白底、可收起、账户钉在底部，展开宽度与协作前台相同，不得另做一套发光导航或更宽的管理侧栏。协作一级菜单约 34px；空间/系统管理菜单项约 44px、间距更松。选中为淡紫色浅底，不得把画布或侧栏铺成紫色。禁止把导航项纵向撑开填满侧栏。三个门户各自挂载外壳，切换时必须直接恢复已保存的折叠宽度，不得把恢复过程播成收起动画。三个门户使用同一套账户下拉，退出登录只出现在该菜单底部。完整风格不变量见 `ux-and-visual.md`。
- 三个区域共享品牌令牌、标志、主题和语言偏好，但不共享页面层级和主要导航。
- 桌面后台采用侧边导航与内容画布；窄屏将导航转换为可横向浏览的分区栏，禁止压缩为不可读的小型桌面页。
- 前后台之间通过账户菜单切换角色，避免仅使用含义模糊的图标，也不在顶栏再放一套语言/主题/角色控件。

## 3. 授权边界

1. `/admin/*` 的每次请求都必须由服务端依据当前会话、工作空间成员状态和 Capability 决定是否放行。
2. 客户端隐藏菜单、保存的主题或语言、URL 参数和本地存储都不是授权证据。
3. 工作空间管理总览要求 `workspace.manage`；安全策略要求 `workspace.security.manage`；审计要求 `audit.read`。
4. 直接访问无权页面时显示不泄露资源细节的拒绝状态，并提供返回协作前台的路径。
5. `/system` 使用独立的平台身份与授权域，禁止把 Workspace Owner 自动提升为系统管理员。
6. 系统人员访问租户内容必须经过限时、具理由、可审计的 Break-glass 流程。
7. 平台模型目录、供应商接入和密钥只属于系统管理员。空间管理员不得自行添加供应商或填写密钥，只能把已分配给本租户的模型配给本空间的 AI。未分配给该租户的模型，服务端必须拒绝选用和调用。

## 3.1 模型由系统管理、再分配给租户

这是页面设计阶段的产品边界，后续实现必须遵守，不能先在空间管理里做一套「自己接模型」。

| 谁         | 做什么                                                                                                               | 不做什么                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 系统管理员 | 接入整套可用模型（有哪些供应商、哪些模型名、密钥只存在服务端）；把模型分配给指定租户；查看平台是否可用、额度是否紧张 | 默认打开某个租户的房间、文档或对话           |
| 空间管理员 | 看到本租户已被分配的模型列表；给本空间的 AI 成员选择其中之一；在已分配额度内看本空间用量                             | 自己接新的供应商、粘贴密钥、使用未分配的模型 |
| 协作成员   | 与已配置好的 AI 一起工作                                                                                             | 配置供应商或模型目录                         |

系统后台的页面设计包含「模型」分区：目录、分配给租户、可用性。当前预览壳已提供 `/system/models`。空间管理的「可用模型」只展示本租户已分配项，不能写成租户自己接入密钥。

## 4. 当前 Alpha 边界

当前实现提供完整可导航的协作前台、工作空间后台与系统后台预览壳。协作前台必须通过邮箱密码登录拿到 HttpOnly 会话；`DEMO_MODE=true` 只决定是否把本地虚拟数据写入 PostgreSQL，不能跳过认证，也不会打开协作服务的固定 ticket。本地开发环境仍用硬编码的 Owner 预览身份授权后台分区，直到服务端按会话 Membership 强制执行；生产构建默认拒绝未认证的后台访问。

工作空间后台的成员列表与 AI 协作者来自服务端快照；尚未接入账本、审计或模型目录的分区展示空态。操作按钮只执行本地界面反馈，不代表已经修改持久数据。任何尚未连接 API 的动作必须通过中央 Toast 说明状态，不得产生成功写入的假象，不得使用常驻横幅，也不得用示例数字或示例事件填满页面。

系统后台提供可导航的平台预览（租户目录、模型、健康、策略、审计）。租户与模型目录在平台 API 接入前保持空态；健康分区只探测 API 就绪接口，不把未接入的依赖显示为可用。禁止展示租户房间、文档或对话内容。登录页保持左右分栏：左侧品牌故事，右侧三角色身份入口与表单。协作成员和空间管理在账号密码下方用下拉选择工作区；系统管理不显示该项。未认证时下拉为空态，邮箱密码在本页登录成功后再根据 `GET /v1/session` 列出并默认选中第一项。未登录不得枚举工作区。账户菜单仅在同一账户加入多个工作区时提供「切换工作区」。

### 4.1 非 AI 协作外壳

在聊天编排、模型供应商和 Agent Run 正式接入前，协作前台先补齐可独立验收的团队工作路径：

- 工作空间总览聚合最近房间和共享文档元数据，待处理事项在收件箱 API 接入前保持空态。
- 收件箱支持在提及、待审批和邀请之间切换；未连接 API 时展示空态，不写入假已读记录。
- 文档目录支持搜索、状态筛选和返回所属房间的文档面板；工具栏搜索占满剩余宽度，筛选与新建收在右侧。目录数据来自服务端快照，不再使用前端假文档。
- 活动记录只展示可归因的人员、时间和对象；事件 API 接入前保持空态。
- 上述页面不得触发模型调用、工具调用或外部写入。阶段边界只出现在空状态或操作后的 Toast，不作为常驻横幅。

视觉层级继续使用 HaloAI 的语义令牌。参考产品只用于校准信息架构、留白和交互密度，不复制其品牌、配色或 AI 权限模型。

## 5. 完成标准

- `/app`、`/admin/overview`、`/system` 以及 `/system/tenants`、`/system/models`、`/system/health`、`/system/policy`、`/system/audit` 可通过真实链接互相导航，且分区路由不得从客户端模块读取校验表。
- 后台桌面与 390px 移动视口无非预期水平溢出，交互目标不小于 44×44 CSS 像素。
- 中文、英文与明暗主题覆盖协作前台、后台和拒绝状态。
- 无权主体不能通过直接输入 URL 绕过服务端守卫。
- 每个后台页面显示当前作用域，并区分已生效、待审批、未连接和只读状态。
- 系统后台默认拒绝 Workspace 角色，且不展示租户内容摘要。
- 总览、收件箱、文档目录和活动记录可从协作前台真实切换，且不触发 AI 或外部写入。
- 1440×900 保持房间、对话、文档三栏；平板和移动端转换为单视图路径，不依赖压缩桌面布局。
- 登录页仅在协作成员和空间管理用下拉选择工作区；未登录为空态，登录后填入会话中的工作区。系统管理不显示该项。账户菜单仅在多个工作区时提供切换。
