# 前台、工作空间后台与系统后台

## 1. 目的

HaloAI 将面向团队的协作体验、工作空间治理和平台运营明确拆成三个界面区域。拆分首先服务于心智模型和最小权限，而不是为了制造更多页面。

| 区域         | 稳定路由   | 使用者                                        | 核心职责                                                                           |
| ------------ | ---------- | --------------------------------------------- | ---------------------------------------------------------------------------------- |
| 协作前台     | `/app`     | 团队成员与受邀访客                            | 房间、消息、文档、AI 协作、审批和成果交付                                          |
| 工作空间后台 | `/admin/*` | Workspace Owner、Workspace Admin 与专项管理员 | 成员、角色、AI（只用已分配模型）、集成、安全、用量与审计                           |
| 系统后台     | `/system`  | 平台运营与安全人员                            | 租户生命周期、整套模型目录与按租户分配、系统健康和平台默认设置；不默认读取租户内容 |

根路由 `/` 只负责进入协作前台，不承载第二份首页。

## 2. 导航与视觉边界

- 协作前台固定为左导航与右工作区：左侧白色菜单和个人设置，右侧灰色当前页面；禁止在主工作区重复左侧一级导航。
- 工作空间后台与系统后台共用协作前台同一套侧栏：白底、可收起、账户钉在底部，展开宽度与协作前台相同，不得另做一套发光导航或更宽的管理侧栏。协作一级菜单约 34px；空间/系统管理菜单项约 44px、间距更松。选中为淡紫色浅底，不得把画布或侧栏铺成紫色。禁止把导航项纵向撑开填满侧栏。三个门户各自挂载外壳，切换时必须直接恢复已保存的折叠宽度，不得把恢复过程播成收起动画。三个门户使用同一套账户下拉，退出登录只出现在该菜单底部。完整风格不变量见 `ux-and-visual.md`。
- 三个区域共享品牌令牌、标志、主题和语言偏好，但不共享页面层级和主要导航。
- 桌面后台采用侧边导航与内容画布；窄屏将导航转换为可横向浏览的分区栏，禁止压缩为不可读的小型桌面页。分区栏下方不得再挂原生下拉或第二套选单来切换分区；页内选项使用分段药丸，抽屉内才使用下拉。
- 空间管理与系统管理的侧栏外壳必须挂在布局层，分区切换只替换内容画布。已收起的侧栏不得因换页重挂载而播放展开或收起动画。折叠宽度同时写入 Cookie，服务端绘制与客户端恢复必须一致。
- 前后台之间通过账户菜单切换角色，避免仅使用含义模糊的图标，也不在顶栏再放一套语言/主题/角色控件。
- 侧栏文字在普通态与选中态都使用清晰的中等粗体；收起为图标轨后，每个导航项、房间和账户入口必须在悬停或键盘聚焦时显示名称提示。

## 3. 授权边界

1. `/admin/*` 的每次请求都必须由服务端依据当前会话、工作空间成员状态和 Capability 决定是否放行。
2. 客户端隐藏菜单、保存的主题或语言、URL 参数和本地存储都不是授权证据。
3. 工作空间管理总览要求 `workspace.manage`；安全策略要求 `workspace.security.manage`；审计要求 `audit.read`。
4. 直接访问无权页面时显示不泄露资源细节的拒绝状态，并提供返回协作前台的路径。
5. `/system` 使用独立的平台身份与授权域，禁止把 Workspace Owner 自动提升为系统管理员。
6. 系统人员访问租户内容必须经过限时、具理由、可审计的 Break-glass 流程。
7. 平台模型目录、供应商接入和密钥只属于系统管理员。空间管理员不得自行添加供应商或填写密钥，只能把已分配给本租户的模型配给本空间的 AI。未分配给该租户的模型，服务端必须拒绝选用和调用。

## 3.1 模型由系统管理、再分配给租户

这是页面设计阶段的产品边界，后续实现必须遵守，不能先在空间管理里做一套「自己接模型」。

| 谁         | 做什么                                                                                                               | 不做什么                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 系统管理员 | 接入整套可用模型（有哪些供应商、哪些模型名、密钥只存在服务端）；把模型分配给指定租户；查看平台是否可用、额度是否紧张 | 默认打开某个租户的房间、文档或对话           |
| 空间管理员 | 看到本租户已被分配的模型列表；给本空间的 AI 成员选择其中之一；在已分配额度内看本空间用量                             | 自己接新的供应商、粘贴密钥、使用未分配的模型 |
| 协作成员   | 与已配置好的 AI 一起工作                                                                                             | 配置供应商或模型目录                         |

系统后台的页面设计包含「模型」分区：目录、分配给租户、可用性。模型目录必须支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 与 Google Generate Content 等显式协议格式，不能用一个“兼容接口”字段掩盖不同请求契约。空间管理的「可用模型」只展示本租户已分配项，不能写成租户自己接入密钥。

模型 API Key 仅在创建或轮换时由系统管理员提交。数据库保存 AES-256-GCM 密文、随机 IV、认证标签与密钥版本，页面和列表响应只返回“已配置/未配置”，禁止回显、日志记录或通过浏览器包注入明文。生产环境必须注入独立的模型密钥加密主密钥；认证密钥不得兼任模型密钥加密密钥。

## 4. 当前 Alpha 边界

当前实现提供完整可导航的协作前台、工作空间后台与系统后台。协作前台必须通过邮箱密码登录拿到 HttpOnly 会话；`DEMO_MODE=true` 只决定是否把本地虚拟数据写入 PostgreSQL，不能跳过认证，也不会打开协作服务的固定 ticket。系统后台由独立的 `system_administrators` 平台授权记录保护，工作空间 Owner 不会自动获得系统权限；租户目录的跨租户读取只能经过检查平台身份的窄 `SECURITY DEFINER` 数据库函数。

工作空间后台的成员、部门组织与 AI 协作者来自服务端快照。成员管理采用「部门树 + 成员目录」结构：部门属于当前工作空间，可形成有限层级并设置负责人、说明与排序；人员成员可设置主部门与岗位，访问角色仍由独立的 Workspace Role 决定，部门不得隐式扩大权限。成员搜索、部门筛选和分页都必须先在已授权的当前空间范围内执行。尚未接入账本、审计或模型目录的分区展示空态。操作按钮只执行本地界面反馈，不代表已经修改持久数据。任何尚未连接 API 的动作必须通过中央 Toast 说明状态，不得产生成功写入的假象，不得使用常驻横幅，也不得用示例数字或示例事件填满页面。

系统管理员创建租户时必须指定一个已经完成身份注册的默认管理员，该人员在同一事务中成为新空间的 Owner；租户目录只展示管理员姓名与邮箱、成员数和部门数等治理元数据，不读取租户房间、文档或对话内容。

系统后台提供总览、租户、模型、健康和系统设置五个稳定分区。策略与审计仍属于工作空间治理，不在平台导航重复出现。总览与租户目录读取真实平台 API；种子写入的工作空间应立即进入统计与目录，不得被前端硬编码空态遮蔽。租户与模型目录使用卡片网格，不用桌面宽表；服务端分页统一使用 1 基页码、10/20/50 每页药丸选项，分页条与容器边缘保持内边距，搜索条件或每页数量变化时回到第一页。模型目录支持登记、更新、启停和按租户分配。系统设置使用与分区导航同一套横向页签，当前只有「通用」与「认证」；平台默认语言、登录有效期、续期间隔和滑动续期由系统管理员在页面保存，写入 `system_settings`，并在签发新会话时生效。环境变量只在数据库尚无对应键时提供启动缺省，不能作为页面上的只读真相，也不得再放无实现的「AI 对话」页签。健康分区只探测 API 就绪接口，不把未接入的依赖显示为可用。所有分区禁止展示租户房间、文档或对话内容。登录页保持左右分栏：左侧品牌故事，右侧三角色身份入口与表单。协作成员和空间管理在账号密码下方用下拉选择工作区；系统管理不显示该项，而是在登录成功后额外验证平台身份。未认证时下拉为空态，邮箱密码在本页登录成功后再根据 `GET /v1/session` 列出并默认选中第一项。未登录不得枚举工作区。账户菜单仅在同一账户加入多个工作区时提供「切换工作区」。

### 4.1 非 AI 协作外壳

在聊天编排、模型供应商和 Agent Run 正式接入前，协作前台先补齐可独立验收的团队工作路径：

- 工作空间总览聚合最近房间和共享文档元数据，待处理事项在收件箱 API 接入前保持空态。
- 收件箱支持在提及、待审批和邀请之间切换；未连接 API 时展示空态，不写入假已读记录。
- 文档目录支持搜索、状态筛选和返回所属房间的文档面板；工具栏搜索占满剩余宽度，筛选与新建收在右侧。目录数据来自服务端快照，不再使用前端假文档。
- 活动记录只展示可归因的人员、时间和对象；事件 API 接入前保持空态。
- 上述页面不得触发模型调用、工具调用或外部写入。阶段边界只出现在空状态或操作后的 Toast，不作为常驻横幅。

视觉层级继续使用 HaloAI 的语义令牌。参考产品只用于校准信息架构、留白和交互密度，不复制其品牌、配色或 AI 权限模型。

## 5. 完成标准

- `/app`、`/admin/overview`、`/system` 以及 `/system/tenants`、`/system/models`、`/system/health`、`/system/settings` 可通过真实链接互相导航，且分区路由不得从客户端模块读取校验表。
- 后台桌面与 390px 移动视口无非预期水平溢出，交互目标不小于 44×44 CSS 像素。
- 中文、英文与明暗主题覆盖协作前台、后台和拒绝状态。
- 无权主体不能通过直接输入 URL 绕过服务端守卫。
- 每个后台页面显示当前作用域，并区分已生效、待审批、未连接和只读状态。
- 系统后台默认拒绝 Workspace 角色，且不展示租户内容摘要。
- 种子租户出现在平台统计和分页目录；模型密钥响应永远不含明文，修改密钥后旧值也不能再次读取。
- 租户与模型目录在桌面和移动端都使用卡片网格；分页、筛选、加载、错误和空状态保持稳定布局，不依赖横向滚动完成主要操作。
- 工作空间成员页可按部门筛选和分页，成员的主部门、岗位与访问角色清晰分列；部门树支持新增、编辑、负责人和有限层级，且部门归属不改变权限。
- 系统管理员可创建租户并指定已注册账户为默认管理员；创建过程原子地建立 Owner，系统租户目录可见默认管理员和部门数量，但不暴露租户内容。
- 总览、收件箱、文档目录和活动记录可从协作前台真实切换，且不触发 AI 或外部写入。
- 1440×900 保持房间、对话、文档三栏；平板和移动端转换为单视图路径，不依赖压缩桌面布局。
- 登录页仅在协作成员和空间管理用下拉选择工作区；未登录为空态，登录后填入会话中的工作区。系统管理不显示该项。账户菜单仅在多个工作区时提供切换。
