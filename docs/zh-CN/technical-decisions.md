# HaloAI 技术决策

## 状态与决策周期

本文档是 HaloAI 当前架构决策记录摘要。它定义首个可用内部 Alpha 的技术边界，下文称为 MVP，同时记录已经确定但会在后续交付阶段启用的方向。

当对应阶段开始时，已采纳的决策具有约束力。延期技术不得在 MVP 中成为必需依赖、部署组件或隐藏的生产假设。替换已采纳决策必须创建新的决策记录，提供可度量证据、数据与协议迁移方案，以及经过测试的回滚路径。

## 纯 TypeScript 的定义

纯 TypeScript 表示：

1. apps 和 packages 中 HaloAI 自有的应用与业务行为使用 TypeScript 编写。
2. Web、API、Worker、实时服务、策略引擎、Agent 运行时、供应商适配器、工具网关和协作编排只要求受支持的 Node.js 运行时。
3. CSS、SQL migration、JSON、Markdown、shell 无关的容器配置和生成产物属于允许的支撑格式。
4. PostgreSQL、对象存储、模型供应商、浏览器和 MCP 服务属于基础设施边界，不是额外的 HaloAI 应用语言。
5. 经过审查的第三方包可以包含编译产物，但 HaloAI 必须通过类型化包边界访问，产品规则不得放入原生扩展。
6. 未来的特殊计算只有在建立独立决策记录后，才可以作为隔离外部服务运行。它不得拥有 HaloAI 身份、授权、房间、文档、审批、记忆或审计事实。

TypeScript 静态类型不能验证网络、模型、数据库或用户输入。每个外部边界都必须使用运行时验证、有界解析、安全默认值和稳定错误契约。

## 包与进程边界

| 边界                   | 所有权                                                                    | 明确排除                                                              |
| ---------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| apps/web               | Next.js UI、PWA 外壳、国际化、无障碍、轻量同源 BFF                        | 不执行长时间 Agent 任务，不消费队列，不拥有授权事实或直接拥有协作状态 |
| apps/api               | Fastify REST/SSE、认证集成、应用命令、策略执行、Webhook 入口、实时 ticket | 不拥有 UI 状态，不执行无界后台工作，不信任客户端 tenantId             |
| apps/worker            | Graphile Worker 任务、Agent 执行、投影、重试、可恢复文档任务              | 不持有公开人类会话，不扩大权限，不产生未记录外部副作用                |
| packages/core          | 领域类型、状态机、不变量、策略输入与输出                                  | 不依赖 Next.js、Fastify、数据库驱动、供应商 SDK 或编辑器              |
| packages/db            | Drizzle schema、repository、事务辅助、migration、RLS 上下文               | 不调用模型，不包含 UI 行为，不把授权决定藏在临时查询中                |
| packages/agent-runtime | ModelGateway、工具适配器、协作路由、上下文与预算机制                      | 不拥有人员身份、访问事实、房间成员关系或审批事实                      |
| packages/contracts     | REST、事件、任务、文档和集成 schema                                       | 不包含框架特有 request 对象或供应商特有 response 类型                 |

Turborepo 可以调度和缓存任务，但包脚本必须可以独立执行。缓存构建成功不能成为正确性的唯一证据。

## 数据与协议演进规则

1. package.json 与 pnpm lockfile 是依赖事实。依赖范围不得在 CI 或生产中静默选择新的 major。
2. 公共 REST 契约、耐久事件信封、Graphile Worker payload、工具 schema、ModelGateway 事件和文档 schema 都携带显式版本。
3. 优先增加字段。读取端可以忽略已记录的未知可选字段，但必须拒绝未知的安全关键 variant。
4. 数据库变更使用 expand、backfill、verify、contract。破坏性 migration 必须与停止使用旧数据的应用发布分开。
5. 事件与任务消费者按稳定 ID 去重，并容忍至少一次投递。
6. Agent 运行记录模型标识、供应商适配器版本、Agent 版本、工具版本、策略版本和预算版本。
7. Yjs/文档 schema migration 在发布前使用已保存 fixture 和混合客户端版本测试。
8. 安全更新可以缩短正常兼容窗口，但仍需记录回滚或隔离方案。

## 系统失败边界

### 耐久事实

PostgreSQL 是身份关联、成员关系、房间、消息、运行状态、审批、预算、审计事实、文档元数据、版本、任务元数据和 Outbox 记录的权威。对象存储是 PostgreSQL 所引用大型不可变 blob 的权威。浏览器存储、Next.js 实例、Fastify 进程、Worker 内存、SSE 连接、WebSocket 连接、缓存、模型供应商和 MCP 服务都不是这些事实的权威。

### Fail-closed 边界

以下故障必须拒绝或暂停工作，不能降级授权：

- 缺少租户、项目、房间、Actor、委托或策略上下文；
- 无法获得认证或授权决定；
- 高风险操作无法获得审批记录；
- Agent、工具、事件、任务或文档 schema 版本未知；
- 无法持久化必要审计事实或预算预留；
- 外部写入状态不确定。

### 可降级边界

以下情况可以降级，但不能破坏耐久事实：

- 模型流 delta 可以停止，同时运行进入可恢复状态；
- SSE 客户端可以重连并重放耐久事件；
- WebSocket presence 可以消失，但文档 snapshot 仍然可读；
- 可选本地缓存和未来分布式缓存可以 miss；
- 以后引入的语义检索可以禁用，同时显式文档访问保持可用；
- 模型或 MCP 供应商不可用时，可以让一个 Agent 贡献失败，但不能禁用人员的房间与文档工作。

## MVP 排除门槛

只有满足以下条件，MVP 才符合这些决策：

1. 干净安装和生产启动需要 Node.js、pnpm、PostgreSQL，以及已声明的对象存储或本地开发适配器，但不需要第二种应用语言。
2. workspace 任务通过 pnpm 与 Turborepo 运行，并且在禁用 Turborepo 缓存时也能成功。
3. Next.js 不在请求生命周期内执行已经确认的长时间 Agent 工作。
4. Fastify 和 Worker 进程重启不会丢失已确认命令。
5. 每个包含产品数据的租户表都具备显式 tenant key、repository 过滤，并在适用 RLS 时具备 RLS 隔离测试。
6. 产品事务和对应 Outbox 事件只能一起提交或一起回滚。
7. 人员认证经过 AuthGateway；任何 AI Actor 都不能获得人类会话。
8. 应用和领域包导入 ModelGateway 契约，而不是供应商 SDK 类型。
9. AI 文档修改进入提案路径，不能通过直接修改编辑器应用。
10. REST、SSE 和 WebSocket 各自具备已定义职责、版本标记、认证握手和重连行为。
11. 运行时与部署 manifest 不包含必需的 Redis、Temporal、向量数据库、Kubernetes、Swift、Kotlin 或原生跨平台应用依赖。
12. 引入任何延期技术都必须提供触发证据、新决策记录、所有者、安全审查、迁移、可观测性、成本估算和回滚测试。
