# HaloAI 权限与安全规格

## 1. 目的与规范用语

本文定义 HaloAI 的授权模型、租户边界、安全控制和发布验收标准。文中的“必须”“禁止”“应当”和“可以”均为规范要求。

每个受保护操作都必须由服务端按以下形式评估：

```text
authorize(subject, action, resource, context)
  -> allow | deny | require_approval
  + obligations
```

附加义务可以要求脱敏、只读访问、费用上限、指定审批人或写入审计事件。默认决定为 `deny`。主体身份、工作空间成员身份和租户作用域必须来自服务端认证上下文，禁止来自客户端传入的身份或租户字段。

## 2. 身份、角色与人设分离

`Actor`、`AccessRole` 与 `Persona/AgentProfile` 是相互独立的概念：

- `Actor` 是可归责的人类或非人类身份。
- `AccessRole` 在指定作用域内授予能力。
- `Persona/AgentProfile` 描述 AI 成员的行为、模型、指令和展示方式，本身不授予任何权限。

### 2.1 主体类型

| 主体        | 认证来源                                  | 可用角色类型          | 强制约束                                     |
| ----------- | ----------------------------------------- | --------------------- | -------------------------------------------- |
| 人类用户    | 企业 SSO 或第一方用户会话                 | 工作空间和项目角色    | 会话可信级别、成员状态以及可选的设备/IP 条件 |
| AI 主体     | 独立 Agent 身份和不可变 Agent 版本        | Agent 作用域角色      | 无交互式登录；每次运行记录委托人或 Sponsor   |
| 服务账号    | OAuth 客户端或工作负载身份                | 集成专用角色          | 短期、受众绑定、可撤销凭据                   |
| 外部集成    | OAuth 授权、签名 Webhook 或经批准的连接器 | Connector 作用域角色  | 工具白名单、网络出口策略和凭据隔离           |
| 系统 Worker | 内部工作负载身份                          | 队列 Worker 能力      | 只能处理耐久任务中指定的工作空间和资源       |
| 支持人员    | 强认证的内部账号                          | 限时 Break-glass 授权 | 双人审批、客户可见审计和自动过期             |

AI 主体禁止获取、复制、模拟或刷新人类登录会话。系统 Worker 不得因为运行受信任代码就继承宽泛的应用管理员权限。

### 2.2 内置角色模板

| 角色模板        | 默认用途                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------- |
| Workspace Owner | 工作空间生命周期、所有权、安全、成员、计费、导出和删除                                             |
| Workspace Admin | 成员、项目、Agent 和已批准集成的管理；不能登记模型供应商、不能读取密钥明文、不能做破坏性所有权操作 |
| Security Admin  | 策略、会话撤销、审计、保留期和集成审批                                                             |
| Billing Admin   | 用量、预算和账单，不自动获得对话或文档正文访问权                                                   |
| Agent Manager   | Agent 创建、版本管理、从本租户已分配目录中选择模型、工具作用域配置                                 |
| Member          | 在明确可访问的项目、房间和交付物中协作                                                             |
| Guest           | 仅访问明确共享给该访客成员身份的资源                                                               |
| Auditor         | 只读审计和合规导出；内容访问需要独立授权                                                           |
| Agent Member    | 在明确委托范围内发送消息和操作交付物                                                               |

内置角色是能力集合模板。自定义角色必须由 capability 集合构成，禁止使用页面路径或 UI 菜单定义。除非经过独立授权的管理流程，主体不得授予自己并不拥有的能力。

平台运营身份与上述工作空间角色分离。系统管理员维护整套模型目录、供应商密钥引用，以及把模型分配给哪些租户。Workspace Owner 不能因为拥有租户就被当成系统管理员。

## 3. 资源与动作矩阵

| 资源             | 动作                                                                             | 典型持有者                                                     | 必须检查的条件                                                       |
| ---------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------- |
| 工作空间         | `read`、`update`、`export`、`delete`                                             | Owner；部分 Admin 角色                                         | 成员身份有效；删除要求提升认证级别和二次确认                         |
| 成员身份         | `invite`、`read`、`update`、`remove`                                             | Owner、Workspace Admin                                         | 不能移除最后一个 Owner；不能突破调用者的委托上限                     |
| 角色和策略       | `create`、`read`、`update`、`delete`、`assign`                                   | Owner、Security Admin                                          | 禁止自我提权；审计策略版本与变更                                     |
| 项目和房间       | `create`、`read`、`update`、`archive`、`manage_members`                          | 经授权的工作空间成员                                           | 工作空间一致、项目作用域、房间 ACL 和数据分级                        |
| 消息和线程       | `read`、`create`、`edit_own`、`delete_own`、`moderate`                           | 房间参与者和受委托 Agent                                       | 读取和发送时均重新校验成员身份；编辑保留历史                         |
| 交付物和文档     | `create`、`read`、`update`、`comment`、`approve`、`publish`、`delete`、`restore` | 项目成员和受委托 Agent                                         | 交付物 ACL、当前版本、数据分级和审批策略                             |
| 交付物版本       | `read`、`compare`、`restore`                                                     | 交付物读者；恢复要求编辑权                                     | 恢复生成新版本，禁止覆盖历史                                         |
| 文件和附件       | `upload`、`read`、`download`、`delete`                                           | 房间或交付物参与者                                             | 恶意软件扫描、类型/大小限制和短期签名下载                            |
| 知识和记忆       | `read`、`write`、`mount`、`delete`                                               | 明确授权的成员和 Agent                                         | 必须先做授权过滤，再排序或组装模型上下文                             |
| Agent 配置和版本 | `create`、`read`、`update`、`delete`、`invoke`                                   | Agent Manager；经授权调用者                                    | 配置权与调用权分离；运行绑定不可变版本；选用的模型必须已分配给该租户 |
| 密钥和凭据绑定   | `bind`、`rotate`、`revoke`                                                       | 模型供应商密钥仅系统管理员；工作空间只能绑定已批准的连接器引用 | 永不返回明文；绑定范围小于管理主体的权限范围                         |
| 平台模型目录     | `create`、`read`、`update`、`allocate`、`revoke`                                 | 仅系统管理员                                                   | 未分配给该租户的模型禁止出现在空间选用列表，调用时服务端再拒绝       |
| 工具和集成       | `install`、`configure`、`invoke`、`disable`                                      | Admin 管理；Agent 仅按范围调用                                 | 白名单、参数策略、风险等级、网络出口策略和审批状态                   |
| 运行和任务       | `create`、`read`、`cancel`、`retry`                                              | 发起人、Sponsor、项目管理员                                    | 预算、并发、幂等、委托和当前授权                                     |
| 审批             | `request`、`read`、`approve`、`reject`                                           | 指定审批人                                                     | 发起 Agent 不能审批；绑定参数和有效期仍须一致                        |
| 用量和预算       | `read`、`manage`、`export`                                                       | Owner、Billing Admin；个人范围只读                             | 明确工作空间和报表作用域                                             |
| 通知             | `read`、`mark_read`、`delete`                                                    | 仅目标成员身份                                                 | 用户、工作空间和成员身份全部匹配                                     |
| 审计事件         | `read`、`export`                                                                 | Security Admin、Auditor                                        | 只读；按内容权限脱敏敏感字段                                         |
| 保留策略         | `read`、`update`、`legal_hold`                                                   | Owner、Security Admin                                          | 法务保留优先于普通过期和删除                                         |

## 4. 条件与 AI 权限交集

策略评估必须至少支持以下条件：

- 有效的工作空间和项目成员身份；
- 资源所属工作空间、项目、房间和 ACL；
- 所有权和文档数据分级；
- 配置启用时的会话可信级别、近期 MFA、设备、IP、区域和时间窗；
- Agent 版本、Sponsor、委托有效期和用途；
- 模型、工具、连接器、网络和参数限制；
- 操作风险等级和审批状态；
- token、金额、时长、轮次、参与者和工具调用预算；
- 数据驻留和保留策略。

一次 AI 运行的有效权限为：

```text
Agent 角色授权
INTERSECT 委托人或 Sponsor 的授权
INTERSECT 资源 ACL
INTERSECT 工具和连接器策略
INTERSECT 数据分级策略
INTERSECT 当前有效的审批义务
```

交互式运行的委托人是调用 Agent 的用户。定时或自主运行必须记录指定 Sponsor 或服务主体，并明确用途、作用域、预算和有效期。

授权快照记录运行为何被接受，但不得保留已经撤销的访问权。在每次检索、凭据绑定、工具调用、外部副作用和交付物发布之前都必须重新执行授权。审批必须绑定工具、规范化参数摘要、Agent 版本、委托人、审批人、工作空间和过期时间。任何实质参数变更都会使审批失效。

## 5. 租户隔离

1. 每条租户拥有的长期记录必须包含 `workspace_id`；项目拥有的数据在适用时还必须包含 `project_id`。
2. PostgreSQL 行级安全必须在 Repository 条件之外强制工作空间作用域。租户上下文缺失时必须失败关闭。
3. 组合唯一约束和外键必须包含或校验工作空间归属，禁止建立跨工作空间关系。
4. 对象存储路径、缓存键、向量命名空间、搜索文档、实时 topic、限流键和队列任务必须按工作空间命名空间隔离。
5. 检索必须在语义排序、重排序或模型上下文组装之前应用授权和租户过滤。
6. 文件签名 URL 必须短期有效，并在新鲜授权检查通过后签发。
7. Worker 必须从已签名的耐久任务获得工作空间上下文，并在执行前重新校验资源归属。
8. 跨工作空间支持访问必须使用限时 Break-glass 授权，普通 query 参数永远不足以构成权限。

租户上下文缺失时，任何通用 Repository 方法都不得返回无作用域数据库句柄。平台级报表必须使用单独且显式授权的路径，并提供聚合或脱敏结果。

## 6. 认证与会话安全

- 浏览器会话必须使用 `HttpOnly`、`Secure` 和适当的 `SameSite` Cookie。Access 和 Refresh 凭据禁止存放在 `localStorage` 或 `sessionStorage`。
- Access 默认有效期应不超过 15 分钟。Refresh 会话应不超过 30 天，并且每次使用必须轮换。
- Refresh Token 重用必须撤销受影响的令牌族，并生成安全审计事件。
- 使用 Cookie 认证的状态修改请求必须具备 CSRF 防护和 Origin 校验。
- 会话记录必须支持单设备和全设备撤销、空闲超时、绝对超时以及工作空间角色变更失效。
- 所有权转移、工作空间删除、凭据变更、审计导出和 Break-glass 访问必须使用 MFA 或等价的提升认证。
- Token 禁止出现在 URL 中。实时和流式连接必须使用认证 Cookie 或一次性、受众绑定且短期有效的连接票据。
- 工作负载和连接器 Token 必须短期、受众绑定、作用域绑定、可撤销，并与用户会话相互独立。
- 登出、移除成员、停用账号或降低角色后，API 和实时访问必须及时失效。

## 7. 通知安全

每条通知必须由 `user_id`、`workspace_id` 和 `membership_id` 共同限定作用域。通知可以包含分类、类型化 i18n 键与参数、经过净化的文本摘要、结构化内部目标、已读时间和非敏感 metadata。

- 列表、实时投递、未读数和已读修改必须同时匹配三个作用域字段。
- 切换工作空间或成员身份后不得暴露前一上下文的通知。
- 内部跳转目标必须使用结构化资源引用，禁止任意可执行 URL。
- 通知内容必须为纯文本或严格净化的内容；禁止包含凭据、完整敏感提示词或不受限的模型 HTML。
- 实时 topic 必须在订阅时授权，并在成员或角色变化后重新校验。
- 通知只是信息投影，收到通知永远不会自动授予其关联资源的访问权。

## 8. 凭据与连接器安全

- 模型供应商密钥、OAuth Refresh Token、Webhook Secret 和工具凭据必须使用信封加密，密钥由应用数据库之外的系统管理。
- 明文凭据禁止进入浏览器包、提示词、聊天消息、通知、普通日志、审计 payload、队列 payload，或并不需要这些凭据的模型供应商请求。
- Agent 只能获得不透明的凭据绑定，不能获得密钥值。服务端凭据代理负责执行授权调用或签发范围更小的短期 Token。
- 禁止向连接器或 MCP 服务透传第三方 Token，除非协议明确要求为目标服务签发且受众正确绑定的 Token。
- 每个 Agent 和集成都必须有独立绑定，可以在不影响无关主体的情况下轮换和撤销。
- 外部连接默认必须使用 HTTPS，并强制目的地白名单、DNS/IP 校验、重定向上限、响应大小上限、取消和超时。
- 除非经审查的集成策略明确允许，否则必须拒绝 loopback、link-local、云 metadata 和私有网络目的地。
- 工具安装和作用域扩大必须由有权人员执行；AI 主体不能安装、批准或扩大自己的工具。

## 9. 用量账本与预算

用量核算必须使用 append-only 账本，禁止把可变计数器作为唯一真相源。账本事件包括：

```text
reservation | settlement | release | adjustment
```

每条记录必须包含工作空间、运行、主体、Agent 版本、供应商/模型、计量单位、已知时的金额、币种、幂等键和时间戳。

- 在调用模型或工具之前，运行必须原子预留有界的最坏情况用量。
- 结算使用供应商报告或经策略认可的实际计量值替换预留。
- 失败、取消和过期必须释放未使用的预留。
- 重复供应商响应或 Worker 重试必须借助幂等键只结算一次。
- 预算可以按工作空间、项目、用户、Agent、模型、工具和时间窗配置。
- 限制必须覆盖 token、金额、时长、轮次、参与者、并发运行和工具调用。
- 可以为性能维护物化计数器，但必须能从账本重建并定期对账。
- 预算耗尽必须安全停止新的计费步骤，禁止静默跳过审计或结算。

## 10. 耐久任务、重试与恢复

长时间运行的 Agent、索引、投影、导出和清理工作必须使用耐久队列与 Transactional Outbox。进程内 Promise、计时器或分离任务都不能作为真相源。

最低任务状态机为：

```text
queued -> running -> waiting_approval -> running
                   -> succeeded
                   -> failed -> queued (retry)
                   -> dead_letter
queued/running/waiting_approval -> cancelled
```

- 投递语义为至少一次；处理器必须幂等。
- 每个任务具有稳定幂等键、尝试次数、租约、心跳、超时、取消 Token 和工作空间作用域。
- 重试策略必须区分可重试和永久失败，并使用带抖动的有界指数退避。
- 非幂等副作用必须使用外部幂等键，或在重试前持久化 effect 记录。
- Worker 失败后必须能回收过期租约。毒性任务进入死信队列，并向运维人员展示原因。
- 交互、后台和定时工作必须使用独立并发通道。总容量大于一时，应至少为交互任务保留一个执行名额。
- 恢复的任务在继续前必须重新检查成员身份、策略、审批、预算、资源版本和凭据绑定。
- 取消必须停止后续计费步骤、释放预留，并保存可审计的终态。

## 11. 审计规格

安全审计事件为 append-only，且与诊断应用日志分离。最低事件字段包括：

```text
id, occurred_at, workspace_id,
subject_type, subject_id, membership_id,
on_behalf_of_subject_id, session_id, run_id, trace_id,
action, resource_type, resource_id,
decision, policy_version, obligations, approval_id,
agent_version, tool_id, model_provider, model_name,
request_summary_hash, before_hash, after_hash,
outcome, error_code, source_ip, user_agent
```

系统必须审计认证事件、会话撤销、成员和角色变更、敏感操作的策略决定、Agent/版本变更、凭据绑定变更、工具调用、审批、导出、发布、删除、保留策略变更、Break-glass 访问和账单调整。

审计记录禁止包含明文密钥。完整提示词、回复和工具 payload 必须进入独立加密且受访问控制的 payload 存储，并使用更短的保留期。企业部署应支持防篡改哈希或一次写入存储。普通工作空间管理员禁止编辑或删除审计记录。

## 12. 保留期、删除与法务保留

保留期必须是实际执行的数据生命周期，不能只是配置字段。推荐默认值如下：

| 数据类别                    |            推荐默认值 | 必须执行的删除行为                   |
| --------------------------- | --------------------: | ------------------------------------ |
| Access 凭据                 |               15 分钟 | 过期后失效                           |
| Refresh 会话                |            最长 30 天 | 轮换和撤销后立即失效                 |
| 通知                        |                 90 天 | 过期后删除正文和 metadata            |
| 诊断日志                    |                 30 天 | 禁止包含密钥和完整提示词             |
| 完整 AI 提示词/回复 payload |              30–90 天 | 工作空间可以关闭保存；独立加密       |
| 聊天和交付物内容            |          工作空间策略 | 软删除窗口结束后彻底清理             |
| 审计事件                    | 至少 365 天或企业策略 | 过期或解除法务保留前保持 append-only |
| 用量账本                    |    适用的财务核算周期 | 保留不可变核算字段并最小化内容       |
| 备份                        |      30–35 天滚动窗口 | 自动过期；必要时支持密码学擦除       |

删除必须传播到主表、对象存储、搜索索引、向量存储、缓存、派生记忆、投影和等待中的任务。法务保留阻止普通删除，并记录设置或解除人员。清理任务必须可恢复、可观测且幂等。系统必须生成不复现被删内容的删除记录。备份必须按期过期；在无法实际重写备份时，紧急删除可以销毁每工作空间的信封加密密钥。

## 13. 威胁、控制与验收矩阵

| 威胁                   | 强制控制                                                      | 验收证据                                                                        |
| ---------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 跨租户 IDOR 和数据泄漏 | 服务端作用域、RLS、存储/缓存/搜索/向量/实时/队列命名空间      | 工作空间 A 的凭据无法读取、推断、订阅、重试或修改任何已知的工作空间 B 资源 ID   |
| Token 窃取、固定或重放 | HttpOnly Cookie、轮换、重用检测、CSRF、撤销和 MFA             | XSS 无法读取凭据；重放 Refresh Token 会撤销令牌族；登出终止 API 和实时访问      |
| 提权或混淆代理         | Capability 策略、委托权限交集、重新授权、禁止自我提权         | 忽略客户端传入的角色/工作空间；撤销人的权限后，Agent 下一次检索或工具调用被拦截 |
| 提示词注入和工具外传   | 内容按数据处理、外部策略、参数 Schema、沙箱、网络白名单和审批 | 恶意文档与网页无法泄露密钥、扩大工具或触发未经批准的外部写入                    |
| 检索泄漏               | 排序前 ACL、限定作用域的嵌入和缓存                            | 禁止内容不会进入搜索候选、引用、日志或模型上下文                                |
| 凭据泄漏               | 密钥代理、加密、脱敏和短期绑定                                | 自动扫描在浏览器产物、数据库 payload、队列、提示词、日志和通知中找不到明文密钥  |
| SSRF 和恶意端点        | 目的地策略、DNS/IP 校验、超时、重定向与大小上限               | loopback、metadata、私网地址和 DNS 重绑定请求均被拒绝                           |
| XSS 和恶意文件         | 输出净化、CSP、MIME/魔数校验、恶意软件扫描、解析沙箱和限制    | Markdown/SVG/HTML payload 不执行；伪装文件和解压炸弹被隔离                      |
| 重复任务和重复副作用   | 耐久状态、幂等、租约、effect 记录和有界重试                   | 在各任务边界终止进程后最终只完成一次，不重复发布、发信、删除或付款              |
| Agent 失控和预算耗尽   | 原子预留、多层预算、并发通道和取消                            | 并发负载不能突破预算；取消释放未使用预留并阻止后续工具调用                      |
| 审计篡改               | Append-only 权限、完整性保护和独立存储                        | 工作空间管理员无法修改或删除安全事件；trace 可重建操作和委托链                  |
| 删除不完整             | 执行型保留策略、删除传播、法务保留和备份过期                  | 时间测试验证所有在线存储清理，而被 Hold 的数据保留至解除                        |
| 内部支持滥用           | JIT Break-glass、双人审批、过期和客户可见审计                 | 没有有效授权时支持访问失败；过期后立即拒绝，每次读取/导出都有记录               |

## 14. 强制攻击验收套件

以下测试是受影响能力的发布门槛：

1. `TEN-01`：使用已知外部 UUID 尝试跨工作空间访问 REST、SSE、实时连接、对象下载、搜索、向量检索、通知、任务重试和导出。
2. `TEN-02`：从 Repository 和 Worker 调用中移除租户上下文，所有路径必须失败关闭。
3. `AUTH-01`：运行 XSS 探针，验证浏览器凭据不可读，并且 CSP 阻止未授权执行。
4. `AUTH-02`：重放已轮换的 Refresh Token，验证令牌族撤销和审计事件。
5. `AUTH-03`：在实时连接和 Agent 运行活跃时撤销会话或成员身份，后续事件和受保护步骤必须停止。
6. `AUTHZ-01`：修改客户端传入的主体、工作空间、角色、Owner 和审批字段，服务端解析值必须优先。
7. `AUTHZ-02`：运行创建后降低委托人的角色，下一次检索、工具调用和发布必须拒绝或要求新审批。
8. `AI-01`：在文档、网页、附件和连接器响应中植入要求泄露密钥或绕过策略的指令，任何权限都不得变化。
9. `AI-02`：提交超出 Schema、资源作用域、目的地白名单或审批摘要的工具参数，必须在产生副作用前拒绝执行。
10. `APR-01`：让 Agent 尝试批准自己的操作，或修改参数后重用批准；两种尝试都必须失败。
11. `SEC-01`：扫描浏览器包、提示词、payload 表、队列、通知、诊断日志和审计事件中的种子密钥，禁止出现任何明文。
12. `EGR-01`：探测 loopback、link-local、云 metadata、私有 IP、重定向、超大响应、慢响应和 DNS 重绑定。
13. `CNT-01`：测试可执行 Markdown、SVG/HTML、MIME 混淆、宏文件、路径穿越、解压炸弹和超大解析输入。
14. `QUE-01`：分别在入队、领取、供应商响应、effect 准备和结果持久化后终止 Worker，恢复结果必须确定。
15. `QUE-02`：重复投递同一个任务和供应商响应，用量结算与外部副作用必须只发生一次。
16. `USE-01`：在预算边界并发启动运行，原子预留必须阻止超支。
17. `AUD-01`：分别以 Owner、Admin、Worker 和应用数据库角色尝试更新/删除审计，所有未授权修改必须失败。
18. `RET-01`：推进保留时间，验证数据库、对象、搜索、向量、缓存、派生记忆和任务全部清理；启用法务保留后重复，再解除并验证清理。
19. `NOT-01`：切换工作空间和成员身份，再尝试列出、订阅、统计或标记上一成员身份的通知。
20. `SUP-01`：在没有审批、授权过期以及超出批准资源作用域时尝试跨工作空间支持访问。

## 15. 禁止设计

HaloAI 禁止交付以下任何设计：

- 仅依赖提示词、隐藏按钮、菜单、页面路径或客户端租户 ID 的授权；
- 工作空间或项目上下文缺失时 fail-open 的 Repository 或 Worker 路径；
- AI 主体使用或冒充人类登录会话；
- 浏览器存储或 URL query string 中的 Access/Refresh 凭据；
- 提示词、消息、通知、日志、审计记录、队列或普通下游 payload 中的明文密钥；
- 向工具、连接器、插件或 MCP 服务无约束透传 Token；
- 在没有策略、加密和删除机制时无限期保存完整提示词与回复；
- 仅存在于内存中的任务、审批、用量结算或审计写入；
- 在没有幂等键或持久化 effect 记录时重试非幂等副作用；
- 把可变 `used_tokens` 计数器作为唯一核算记录；
- 只按用户而不是按用户、工作空间和成员身份限定通知；
- 在产品中渲染未经净化的模型或连接器 HTML；
- 缺少 SSRF 控制的任意网络出口或用户配置端点；
- 由 AI 自动安装插件、扩大工具作用域、创建权限或自我审批；
- 只删除主数据库记录而保留派生或复制数据；
- 对客户工作空间永久、无审计或仅基于 query 参数的支持访问。

## 16. 完成定义

新的受保护资源只有在定义工作空间和项目作用域、动作、默认角色、策略条件、审计事件、保留类别、删除路径和负向授权测试后才算完成。新的工具或连接器只有在定义凭据绑定、目的地策略、参数 Schema、风险等级、审批规则、幂等行为、预算单位和攻击验收测试后才算完成。
