# HaloAI 安全基线

## 安全立场

每个 AI 成员都应被视为一个不可信、权限受限的服务主体。模型可以提出操作建议，但只有应用策略能够决定该行为是允许、需要审批还是必须拒绝。

## 不可妥协的控制

1. 每一条长期数据和查询都必须带工作空间与项目作用域。
2. 在检索、调用模型和调用工具之前执行服务端授权。
3. 模型密钥和工具凭据不得进入浏览器包、提示词或普通日志。
4. 上传内容、网页、模型输出和 MCP 结果都按不可信数据处理。
5. 对外、破坏性、财务、发布和权限修改操作默认要求审批。
6. AI 不能创建角色、提升权限、批准自己的行为或扩大工具范围。
7. 每次运行都必须有 token、时长、工具调用和参与者上限。
8. 审计事件记录主体、委托来源、输入摘要、策略决定、工具、结果摘要和审批人。

## 提示词注入边界

- 将检索资料标记为数据，而不是指令。
- 把策略和工具白名单保留在模型上下文之外。
- 通过 schema、资源归属和实时权限重新验证工具参数。
- 语义排序之前先按授权范围过滤检索数据。
- 禁止把第三方 access token 透传给 MCP 服务。
- 只有任务明确需要时才开放网络和文件能力，并限制作用域。

## 权限层级

- 平台级：仅运营方可操作的部署、全局安全和整套模型目录（接入、密钥、按租户分配）。
- 工作空间级：所有权、成员、在已分配目录内为 AI 选模型、保留策略。
- 项目级：房间、文档、知识与参与者范围。
- 资源级：读取、编辑、发布、删除和分享。
- 工具级：调用范围、风险等级与审批规则。

## 上线门槛

接入真实模型或工具之前，必须完成真实认证会话、租户行级隔离测试、密钥加密、限流与滥用控制、依赖扫描、CSP/安全响应头以及经过演练的事故响应流程。
