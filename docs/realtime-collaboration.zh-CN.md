# HaloAI 实时协作规格

## 目的

本文定义 HaloAI 的消息一致性、SSE 恢复、协作文档同步、在线状态、AI 文档提案、PWA 与离线行为。

目标不是不计代价地让所有交互即时发生，而是让协作可预测：已经接受的用户意图不会重复，长期工作可以跨越断线保存，授权始终由服务端执行，并且用户总能理解本地视图是否为最新状态。

## 不变量

1. 由 PostgreSQL 支撑的领域记录是房间、消息、运行、提案、审批、版本和审计事件的长期事实来源。
2. Yjs 二进制状态是协作文档的事实状态；JSON、HTML 和纯文本都是派生投影。
3. Presence 是临时状态，绝不授予访问权限。
4. 长期标识、时间戳、流序号和 Actor 归属均由服务端分配。
5. 客户端重试必须幂等，不能创建重复消息、工具调用、审批或文档操作。
6. 每个实时连接必须针对具体租户、工作区、房间、文档或运行完成授权；作用域缺失时默认拒绝。
7. AI 不得获得人类会话。每个 AI 事件和文档操作都必须记录 Agent 身份、委托人、Profile 版本与运行标识。
8. 短暂传输故障不得变成永久的“正在生成”或“正在保存”状态。
9. 客户端可以乐观显示，但不能成为权限、完成状态或长期顺序的权威来源。

## 协作拓扑

```text
Web / 已安装 PWA
  -> REST 命令与快照查询
  <- SSE 房间事件与 Agent 运行事件
  <-> Hocuspocus WebSocket，传输 Yjs 与 Awareness

API
  -> 授权与幂等性
  -> 消息、运行、提案和审批事务
  -> 长期事件 / outbox 记录

Worker
  -> 可恢复 Agent 执行
  -> 文档投影与压缩

PostgreSQL
  -> 长期领域记录、重放游标、Yjs 快照与审计
```

REST 接受命令并返回权威确认；SSE 传输有序的服务端到客户端事件；Hocuspocus WebSocket 传输文档同步与临时 Awareness。任何传输方式都不得绕过普通 API 请求所使用的服务端授权策略。

## 消息模型

### 长期消息

一条消息至少包含：

```text
id
workspaceId
roomId
actorId
actorType
clientMutationId
replyToMessageId?
threadRootId?
status
createdAt
editedAt?
deletedAt?
agentRunId?
```

消息内容由类型化 part 表示，例如文本、文档引用、附件引用、来源引用、工具摘要、审批引用和系统事件。Mention 以明确关系保存；决定调用哪些 AI 时，不得重新解析渲染后的文本。

消息采用追加式设计：

- 编辑创建 revision，并保留责任归属。
- 删除根据保留策略创建 tombstone。
- 重试 AI 回复时创建另一回复版本或运行，不覆盖历史。
- 附件是独立授权资源，不是不受约束的行内载荷。

### 发送生命周期

1. 客户端生成密码学强度的 `clientMutationId`，并创建乐观本地消息。
2. API 验证人类会话，并从可信服务端上下文推导租户和房间作用域。
3. API 验证内容、附件引用、Mention、速率限制与 `message.create` 权限。
4. 一个事务写入消息、Mention 关系、所需 Agent 任务和 outbox 事件。
5. `(actorId, roomId, clientMutationId)` 唯一约束使重试返回已有消息。
6. API 返回权威消息 ID、服务端时间戳与房间流游标。
7. 客户端替换乐观身份，不能重新挂载或在视觉上复制消息气泡。

失败行为：

- 验证和授权错误留在行内，并保留草稿。
- 网络结果不明确时使用同一 mutation 标识重试。
- 对同一用户意图，客户端不得自动生成第二个 mutation 标识。
- 只有人类消息事务提交后才可排队 Agent Mention。

### 顺序

创建时间是展示元数据，不是并发原语。房间长期顺序使用服务端分配的单调递增 room sequence。线程使用相同房间序列和明确的父级关系。客户端可暂时把乐观消息放在最新权威消息之后，收到服务端序号后再完成对账。

## 实时事件信封

每个长期 SSE 事件使用带版本的信封：

```text
eventId
streamId
seq
type
workspaceId
roomId?
runId?
occurredAt
payloadVersion
payload
```

规则：

- `seq` 在单个 `streamId` 内严格递增。
- 序列绝不能跨租户共享。
- `eventId` 全局唯一且可安全记录，不包含秘密。
- 事件载荷只包含引用和已授权展示数据，不包含凭据或不受限制的领域行。
- 客户端忽略未知的可选事件类型，并记录遥测。
- 遇到未知的破坏性载荷版本时停止该流，并触发快照刷新。

初始事件族：

```text
room.message.created
room.message.revised
room.message.deleted
room.member.changed
room.unread.changed
run.queued
run.started
run.progress
run.text.delta
run.approval.required
run.completed
run.cancelled
run.failed
proposal.created
proposal.changed
approval.resolved
```

进度事件描述读取已授权文档、应用已批准提案等可观察阶段，不能包含模型隐藏推理。

## SSE 订阅与恢复

### 订阅握手

1. 客户端获取权威房间或运行快照。
2. 快照响应包含 `streamId` 与 `snapshotSeq`。
3. 客户端使用 `after=snapshotSeq`，或等效的最后事件游标订阅。
4. API 重新验证会话与精确流的访问权限。
5. 服务端重放游标之后仍被保留的事件，再切换到实时传输。
6. 心跳维持中间网络设备与客户端存活检查。

快照与订阅边界必须避免竞争。在快照查询后提交的事件，其序号大于 `snapshotSeq`，因此仍可恢复。

### 客户端 reducer

客户端为每个流保存已经连续应用的最大序号。

- `seq <= appliedSeq`：作为重复事件忽略。
- `seq === appliedSeq + 1`：应用并前进。
- `seq > appliedSeq + 1`：暂停可见状态归并，获取缺失区间，再继续。
- 事件属于其他 `streamId`：从当前 reducer 中拒绝。

Reducer 必须确定且幂等。同一事件应用两次仍产生相同用户可见状态。长期状态来自事件载荷或刷新后的快照，不能由事件到达时间决定。

### 重连策略

- 使用带抖动的指数退避，约为 1、2、4、8、16 秒，随后最高 30 秒。
- 两秒内恢复的连接不显示错误 Toast。
- 超过两秒后只显示一个低干扰重连提示。
- 重连期间保持当前可读内容可见。
- 短期凭据过期时刷新一次，刷新失败后才要求登录。
- 重连发送最后一个连续序号，而不是最后一个曾经观察到的事件序号。

### 重放缺口与过期

请求序号不再保留时：

1. 服务端返回重放已过期信号。
2. 客户端获取新的权威快照。
3. 原子替换受影响流的状态。
4. 从新的 `snapshotSeq` 之后重新订阅。

Agent 增量文本事件可在完成后压缩，因为最终长期消息才是权威结果。压缩绝不能删除最终回复、来源引用、用量摘要、工具/审批记录或审计归属。

### 流式数据与背压

- 缓冲模型 delta，约每 50–150ms 或达到小载荷阈值后发出一个数据块。
- 不得为每个 token 持久化或渲染一个事件。
- 每个 delta 都有运行内序号和稳定 content part 标识。
- 慢客户端应断开并通过游标恢复；服务端不得维持无限增长的单连接缓冲区。
- SSE 响应使用 no-store 缓存，并发送周期性心跳注释或事件。
- 终态 `completed`、`cancelled` 或 `failed` 只有在此前数据块全部提交后才关闭运行流。

### 取消

客户端使用带幂等键的 REST 取消命令。运行进入 `cancelling`，直到 Worker 确认中止。只有长期 `run.cancelled`、`run.completed` 或 `run.failed` 事件才是终态。仅关闭浏览器连接不会取消运行。

## 多标签页行为

- 每个标签页维护正确游标，并可独立恢复。
- 本地广播通道可以共享未读数、消息确认和连接提示，但不能成为授权或长期状态依据。
- 如果以后引入单标签连接领导者，领导标签失效后，其他标签必须接管，并保留最后长期游标。
- 登出或切换账户时，所有标签页都要清除本地流状态。

## 协作文档状态

### 权威 Yjs 文档

每份协作文档具有稳定文档 ID 与 Yjs 状态。可以使用命名 fragment 分离标题与正文；批注、审批、权限和审计仍应是明确领域记录，除非经过专门 schema 决策将它们放入共享文档。

持久化规则：

- 将 Yjs 状态保存为二进制字节。
- 已经参与协作的文档不得在每次连接时从 JSON 重建；这会创建新历史并可能导致内容重复。
- 保存防抖工作快照和明确版本检查点。
- 记录文档 schema 版本和快照校验值。
- 异步生成 JSON、HTML 与纯文本投影，供搜索、预览、导出和已授权 AI 上下文使用。
- 投影失败不能使权威 Yjs 状态失效。

建议持久化节奏：

- 普通工作快照防抖约一秒。
- 持续变更时最大延迟约五秒。
- 优雅关闭时刷新待保存状态。
- 发布、接受 AI 提案、命名版本和权限敏感转换立即创建检查点。

### Hocuspocus 连接授权

1. 客户端请求短期、单文档协作 ticket。
2. API 验证租户、工作区、文档、当前 Actor 与读写能力。
3. Ticket 绑定文档 ID、Actor ID、能力、有效期和 nonce。
4. Hocuspocus 验证 ticket，并在服务端推导文档名称。
5. 只读参与者可以接收同步状态，但不得提交更新。
6. 能力过期或被撤销时关闭连接或降级为只读。

文档 ID 和 WebSocket 参数只是选择器，绝不是权限证明。长期 session token 不得放入 URL 或日志。

### 更新处理

- 应用前验证编码更新大小和连接速率。
- 将已接受更新归属到连接 Actor 上下文。
- 服务端发起的 AI 更新必须标记 Agent ID、委托人、运行 ID、提案 ID 和 transaction origin。
- 拒绝来自只读或已过期连接的更新。
- 重连时交换 Yjs state vector，只传输缺失更新状态。
- 防御格式错误更新、超大文档与更新洪泛。
- Schema 不兼容客户端进入只读模式，完成更新前不能编辑。

Yjs 负责解决并发结构变更，但不能替代产品授权、版本、审批或语义冲突处理。

## Presence 与 Awareness

Presence 使用 Yjs Awareness 或等价临时通道，只允许包含最小展示信息：

```text
actorId
actorType
displayName
avatarReference?
presenceColor
cursorOrSelection?
clientInstanceId
```

Presence 不得包含电子邮箱，除非它本来就获准展示；也不得包含访问 token、权限、提示词内容、私密文档数据或模型凭据。

规则：

- Presence 不得作为文档内容持久化，也不是审计事实。
- 授权独立于 Presence 进行判断。
- 光标与选区更新必须节流。
- 断开或心跳过期后，过时客户端必须消失。
- 界面最多直接显示五个协作者头像，其余使用 `+N`。
- 辅助技术可以获得 Actor 类型，且身份不能只靠颜色表达。
- AI Presence 表示一次正在发生且可归属的文档事务或审阅会话，不能伪造为永远在线的队友。

## AI 文档提案

### 提案契约

AI 默认不能任意修改文档，而是创建包含以下内容的提案：

```text
proposalId
documentId
baseVersionId
baseStateVector?
agentId
agentProfileVersion
delegatedByActorId
runId
operations[]
rationale
citations[]
createdAt
expiresAt?
```

初始操作类型必须保持狭窄：

- 追加章节
- 替换由稳定 node ID 标识的章节
- 插入批注
- 建议标题
- 添加摘要

不接受任意字符偏移、无限制替换整份文档、可执行内容和权限修改操作。

### 提案状态机

```text
draft
-> pending_review
-> accepted | partially_accepted | rejected | stale | expired
-> applying
-> applied | apply_failed
```

执行 AI 不能批准自己的提案。批准必须绑定到精确提案版本和已选择操作的 hash。

### 审阅与应用

1. 展示可无障碍操作的修改前后差异和来源列表。
2. 允许审阅人接受选择项、全部接受、拒绝或要求修改。
3. 重新验证审阅人权限和提案有效期。
4. 比较当前文档版本/状态与提案基准。
5. 目标章节发生不兼容变化时把提案标记为 stale。
6. 通过服务端控制的 Yjs 事务应用已接受操作，并记录完整 origin 元数据。
7. 持久化新 Yjs 状态，创建版本检查点并追加审计事件。
8. 只有长期事务提交后才发送提案与文档事件。

当稳定 node 身份与 schema 验证可以使结果无歧义时，独立章节变化可安全 rebase。存在歧义的冲突必须刷新差异或重新生成提案，绝不能静默强制应用。

## PWA 生命周期

### 安装与更新

- 提供完整 manifest、standalone 展示模式、主题元数据，以及普通与 maskable 图标。
- 只有用户完成一项有价值操作后才建议安装。
- 首次使用引导不得被安装提示打断。
- 新应用版本准备好时显示不阻塞的更新提示。
- 文档存在未同步本地工作时，不得激活不兼容更新。
- 应用与文档 schema 不兼容时，继续编辑前必须安全刷新。

### 缓存策略

| 资源 | 策略 |
| --- | --- |
| 带版本的应用外壳、图标与字体 | 预缓存，或使用带版本名称的 cache-first |
| 导航 | network-first，离线时回退到应用外壳 |
| 公开不可变资源 | stale-while-revalidate |
| 登录、权限、审批与审计 API | network-only 且 no-store |
| SSE 响应与运行流 | 绝不缓存 |
| 已授权的最近消息/文档摘要 | 仅在策略允许时进入可选本地存储 |
| 附件与敏感文档 | 默认不缓存 |

本地数据按账户、租户、工作区和资源 ID 分区。登出、账户切换、远程会话撤销和缓存 schema 升级时，必须清除或使对应私密数据失效。浏览器存储只是可恢复的便利存储，不能被视为可信安全保险库。

## 离线行为

### MVP 离线范围

支持：

- 离线打开已缓存应用外壳。
- 查看明确允许缓存的最近房间和文档摘要。
- 在本地保存未发送消息草稿。
- 清晰展示离线状态和最后同步时间。
- 复制本地内容用于恢复。

MVP 不支持：

- 恢复联网后自动发送 AI 调用。
- 离线批准敏感操作。
- 未经新的人工意图就重放 Agent Mention。
- 离线发布、删除、分享或修改权限。
- 承诺完整离线协作文档编辑。

离线草稿不是已发送消息。恢复连接后，用户必须重新检查并明确发送。这样可以避免原有上下文已经变化很久后，仍自动触发昂贵或敏感的 AI 运行。

### 未来离线文档编辑

只有产品实现以下能力后，才可启用完整 Yjs 离线编辑：

- 按账户和文档分区本地状态
- 登出与撤销时可靠清除缓存
- Schema migration 与旧客户端阻止机制
- 上传前重新验证权限
- 对已经无法提交的本地编辑提供清晰体验
- 存储配额与文档大小控制

启用后，本地更新通过 Yjs state vector 同步。接受更新前仍要重新授权；拥有本地字节绝不证明当前拥有编辑权限。

### Push 通知

- 只有用户体验到产品价值后才请求通知权限。
- 支持按工作区、房间、Mention、审批和完成事项配置偏好。
- 支持免打扰时段。
- 默认不在锁屏展示敏感消息正文。
- 使用 locale 感知的深链接进入精确工作区、房间、消息、提案或审批。
- 通知只是提示；打开后仍必须执行当前授权检查。

## 安全与隐私边界

- SSE 与 WebSocket 握手必须完成已认证、带作用域的授权。
- 命令和连接 ticket 签发遵守 Origin 与跨站请求保护。
- 短期协作 ticket 必须绑定 audience，且只能用于单一目的。
- 渲染后的 AI 文本、富文本、来源预览和导入 HTML 都是不可信数据，必须通过 allowlist 渲染器。
- 连接日志必须清除 token、消息正文、文档内容和私密提案参数。
- 根据需要按租户、Actor、IP 风险信号、房间、文档和运行执行速率限制。
- 权限撤销必须在有限时间内传播到活动流和协作连接。
- 最终审计记录与临时传输事件分离，并遵守配置的保留策略。

## 默认限制与保留

初始防御性默认值，可根据真实产品数据调整：

```text
消息文本                       64 KiB
单个 SSE 事件载荷              64 KiB
典型文本 delta 数据块          1–8 KiB
单个 Awareness 载荷             2 KiB
Awareness 更新                每客户端每秒不超过 20 次
单个编码 Yjs 更新               1 MiB
编码协作文档                   20 MiB
活动实时连接                   按用户和租户设置上限
```

附件使用独立上传路径，并拥有独立的类型、大小、扫描和存储策略。

建议重放策略：

- 长期房间事件重放至少保留 24 小时，或保留等价的有界序列窗口。
- Agent delta 事件在终态后至少保留 24 小时，随后压缩为权威消息和运行摘要。
- 提案、审批、版本、来源、用量和审计记录根据工作区策略保留，不能随流数据块一起丢弃。

## 性能目标

- 在部署区域内，权威消息确认通常在 500ms 内到达，不含附件上传。
- 已收到的 SSE 事件在 100ms 内进入可见状态。
- 文本 delta 批量渲染，每秒不超过约 20 次视觉更新。
- 同区域协作文档变化通常在 250ms 内远端可见。
- Presence 在不超过配置更新速率的情况下保持流畅。
- 正常 SSE 与 Yjs 重连在五秒内重新收敛。
- 存在数千条历史消息的客户端不得订阅或在内存保留全部历史。
- 慢连接不能造成服务端内存无限增长。

## 验证矩阵

### 消息与 SSE 测试

- 使用同一 mutation ID 重复发送时，只创建一条消息和一次 Agent 调用。
- 结果不明确的超时在重试后返回已有权威消息。
- 重复、延迟和乱序事件最终归并为一个正确状态。
- 序号缺失时触发区间恢复。
- 重放游标过期时触发快照替换。
- 流式过程中刷新页面仍可恢复文本与终态。
- 取消、完成与失败竞争只产生一个终态结果。
- Token 过期只刷新一次，绝不泄露其他租户事件。
- 两个浏览器上下文获得相同房间顺序和各自独立未读状态。

### 文档协作测试

- 两个已认证浏览器上下文同时编辑并最终收敛。
- 断线、允许情况下的本地编辑和重连不会产生重复内容。
- 只读客户端不能提交更新。
- 权限被撤销后，活动编辑器降级或断开。
- 格式错误、超大和洪泛更新被安全拒绝。
- 保存的二进制状态重新加载时不从投影重建历史。
- 投影失败时权威文档保持完整。
- Schema 不兼容客户端不能继续写入。

### 提案测试

- AI 不能批准自己的提案。
- 批准只对精确提案和所选操作 hash 有效。
- 目标章节过期时阻止静默应用。
- 即使命令重试，已接受操作也只应用一次。
- 结果检查点、Actor 归属、来源与审计事件完整。
- 已拒绝和已过期提案不能修改文档。

### PWA 与离线测试

- 应用外壳可离线打开，且不会暴露其他账户数据。
- 登出和账户切换清除私密本地状态。
- 离线草稿在刷新后保留，但不会自动发送。
- SSE、授权、审批与审计响应绝不会从缓存提供。
- 本地工作尚未同步时，应用更新必须等待。
- Push 深链接展示目标前重新进行授权。

## 完成定义

实时协作只有满足以下条件才算完成：

- 消息命令幂等且由服务端排序。
- 每个 SSE 流都能从重复、缺口、断线、刷新和重放过期中恢复。
- 服务端运行已终止后，客户端不会永久卡在非终态。
- Yjs 二进制状态可跨重启保存，并发编辑最终收敛。
- Hocuspocus 连接执行当前文档能力限制。
- Presence 保持临时、最小且不具权威性。
- AI 文档修改使用可审阅提案和可归属的服务端事务。
- 离线行为绝不会静默调用 AI 或批准敏感工作。
- 缓存、流、WebSocket 和多标签页行为均保持账户与租户边界。
- 性能、限制、恢复、安全与跨浏览器测试全部通过。
